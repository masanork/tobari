# Tobari デモ・実施ガイド (Demo Guide)

このガイドは、Tobariプロジェクトのデモを、AI（LLM）と連携して効果的に実演するための手順書です。

## 1. デモの準備と再現性の担保

LLM（Claude Desktop等）には「記憶」があるため、デモのたびに挙動が変わる可能性があります。再現性を高めるために以下の手順を推奨します。

### セッションの初期化
- **必ず「新しいチャット」から開始**: 以前の会話のコンテキストが残っていると、ツールを使わずに「以前の結果」を捏造して回答することがあります。
- **デモ・マスター・プロンプトの投入**: セッションの最初に、以下の「役割定義」をLLMに貼り付けてください。

### デモ・マスター・プロンプト
> **Role**: あなたは Tobari (戸張) プロジェクトのデモ・エージェントです。
> **Context**: ユーザーはデジタル証明書 (mdoc/COSE形式) を持っており、あなたの役割はツールの呼び出し (read_tobari_file, analyze_service_request 等) を通じて、ユーザーの行政手続きを支援することです。
> **Policy**: 
> - バイナリデータ（.cose等）は直接読まず、必ずツールを使って JSON に翻訳してから内容を判断してください。
> - プライバシーを重視し、必要最小限の項目開示 (Selective Disclosure) をユーザーに提案してください。
> - 住民票には「世帯員」という配列があり、家族一人一人の属性が含まれていることを理解しています。
> - 回答は簡潔に、かつ「AIが中身を正しく理解した」ことが伝わるようにしてください。

## 2. メイン・シナリオ：保育園入園の自動試算

このシナリオでは、AIが複数のドキュメントを読み取り、自治体のルールに基づいて選考指数を試算する様子をデモします。

| 手順 | デモラーの語り (Script) | 投入プロンプト (Prompt) | 期待される挙動 |
| :--- | :--- | :--- | :--- |
| **Step 1** | 「まずは区役所からのリクエストを読み込ませて、何が必要かAIに判断させます」 | `examples/service-request/daycare-enrollment.cose` を読み取って、内容を説明して。 | `analyze_service_request` を呼び出し、住民票と就労証明書が必要なことを提示。 |
| **Step 2** | 「次に私の住民票を渡します。AIは家族構成を理解できるでしょうか」 | この住民票 `examples/juminhyo/juminhyo-plain.cose` を使って、家族の状況をチェックして。 | `read_tobari_file` を実行。「4名世帯で2歳のお子さんが2名いますね」等と回答。 |
| **Step 3** | 「さらに就労証明書を渡します。これでAIは点数計算に必要な情報を揃えます」 | 就労証明書 `examples/work-cert/work-cert.cose` も確認して、入園の可能性を試算して。 | `read_tobari_file` を実行。両親フルタイム（160h）を確認し、「42点」等の試算を提示。 |
| **Step 4** | 「最後に、区役所に提出する最小限のデータを作成させます」 | 申請に必要な最小限の項目（住所、家族、勤務状況）だけを開示した提出用データを作成して。 | `create_presentation` を実行し、ネイティブのプレビュー画面（GUI）を起動。 |

## 3. 応用シナリオ：本人確認と端末登録 (Holder Binding)

マイナンバーカードを実際に読み取り、将来的な「カードレス運用」をデモする強力な流れです。

| 手順 | デモラーの語り (Script) | 投入プロンプト (Prompt) | 期待される挙動 |
| :--- | :--- | :--- | :--- |
| **本人確認** | 「最新の情報を確認するため、マイナンバーカードを読み取らせます」 | マイナンバーカードから基本情報を読み取って。 | `read_basic_info` を実行。**ネイティブのPIN入力ダイアログ**が開く。 |
| **端末登録** | 「次回からカードなしで手続きできるよう、この端末に情報を登録します」 | 次回からカードなしで手続きできるように、この端末を登録して、ローカル住民票を発行して。 | `register_device` → `issue_local_credential` の順にツールが実行される。 |

## 4. 新シナリオ：行政申請の自動入力 (Automatic Prefill)

このシナリオでは、ウォレットに保存された「斉藤太朗」さんのデモデータ（または実際のマイナカード）を使用して、Webフォームを一瞬で埋める様子をデモします。

### 事前準備
1.  **デモデータの生成**: `bun scripts/gen-demo-assets.ts` を実行し、`examples/demo-assets/generated/` に斉藤太朗さんの証明書を用意します。
2.  **サーバー起動**: `bun scripts/run-prefill-demo.ts` を実行し、デモ用サーバーを起動します。
3.  **ブラウザでアクセス**: `http://localhost:3000/examples/service-request/prefill-demo.html` を開きます。

### 実演フロー

| 手順 | デモラーの語り (Script) | 操作 / プロンプト | 期待される挙動 |
| :--- | :--- | :--- | :--- |
| **Step 1** | 「今回、デモ用のペルソナとして斉藤太朗さんの身分証を用意しました」 | ブラウザでデモページを表示。 | 氏名・住所が空の「児童手当認定請求書」が表示される。 |
| **Step 2** | 「マイナンバーカードをリーダーにかざします。AIがカードを検知し、安全にデータを抽出します」 | ブラウザの「カードを読み取る」ボタンをクリック。 | ネイティブの `signer-macos` が起動。読み取り完了後、フォーム上部に「JPKIから自動入力」ボタンが出現。 |
| **Step 3** | 「ボタン一発で、住民票に記載された正しい情報がフォームに流し込まれます。入力ミスはありません」 | 「JPKIから自動入力」をクリック。 | 氏名、住所、生年月日、マイナンバーが瞬時に埋まる。 |
| **Step 4** | 「最後に、端末の Secure Enclave を使ってこの申請書に署名し、安全に提出します」 | フォーム下部の「署名して提出」をクリック。 | 署名済み JSON ファイルが生成・ダウンロードされる。 |

### デモのポイント
- **斉藤太朗 (TARO SAITO)**: 生年月日 1985-01-01、住所 東京都千代田区... という一貫した設定を使用しています。
- **名前空間**: `io.github.masanork.tobari.juminhyo.v1` 等の名前空間により、政府ドメインとの衝突を避けた「クリーンなデモ」であることを強調できます。
- **ハイブリッド暗号**: `.enc.cose` ファイルはデモ用共通鍵で保護されており、誰の環境でも（物理カードがなくても）再現可能な「フォールバック・デモ」としても機能します。

## 5. 応用シナリオ：電子委任状の作成と送付 (Power of Attorney)

このシナリオでは、斉藤太朗さんが代理人（あなた）に対して、児童手当の手続きを委任する「電子委任状」をスマホで作成・署名し、デジタルで送付する様子を実演します。

### 実演フロー

| 手順 | デモラーの語り (Script) | 操作 / プロンプト | 期待される挙動 |
| :--- | :--- | :--- | :--- |
| **Step 1** | 「忙しい斉藤さんに代わって、私が児童手当の手続きを行うため、電子委任状を作ってもらいます」 | ブラウザで委任状フォームを表示。 | 宛先が「千代田区長 殿」の委任状が表示される。 |
| **Step 2** | 「斉藤さんは自分のスマホでマイナンバーカードをかざし、住所・氏名を一瞬で入力します」 | 「カードを読み取る」→「JPKIから自動入力」をクリック。 | 委任者の欄に斉藤太朗さんの情報が自動入力される。 |
| **Step 3** | 「受任者（代理人）の欄には私の情報を入力し、委任事項を確認します」 | 代理人欄にあなたの情報を手入力。 | 委任事項「児童手当の認定請求に関する一切の権限...」を確認。 |
| **Step 4** | 「斉藤さんが Secure Enclave で署名すると、改ざん不可能な電子委任状が完成し、私に送られます」 | 「署名して提出」をクリック。 | 署名済み委任状（JSON/COSE）がダウンロードされる。 |

### デモのポイント
- **真正性の連鎖**: マイナカードで本人確認（Prefill）されたデータに対し、端末の鍵で署名することで、作成プロセスの信頼性を担保しています。
- **デジタル・バトン**: 紙の委任状と印鑑の代わりに、デジタル署名されたデータを受け渡しすることで、後続の行政手続き（Step 4）へシームレスに繋がります。

## 6. トラブルシューティング

- **AIがツールを使わない場合**:
  「まずツールを使って中身を確認し、その結果に基づいて回答してください」と指示してください。
- **パスが見つからない場合**:
  プロンプトにはプロジェクトルートからの相対パス（`examples/...`）を明記しています。もし環境が特殊な場合は、絶対パスを教えてあげてください。
- **デモ用GUIが表示されない**:
  `tobari-signer` が正しくビルドされているか、`TOBARI_SIGNER_PATH` が正しく設定されているかを確認してください。
