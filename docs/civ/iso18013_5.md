# ISO/IEC 18013-5 (mDL) and ICAO DTC Implementation Note

## 1. Goal
Export verified identity data from physical cards (JPKI, Passport, Drivers License) into standardized digital formats:
- **mDoc (ISO/IEC 18013-5)**: Used for Mobile Driving Licenses.
- **ICAO DTC (Digital Travel Credentials)**: Type 1 derived from eMRTD (ePassport).

## 2. Data Structure (mDoc)
mDoc uses **CBOR** for data encoding and **COSE** for signatures.

### IssuerSigned
Government-signed part. Contains a list of "Items" (e.g., Given Name, Photo) along with their digests.
- **Namespace**: `org.iso.18013.5.1` (mDL) or `urn:icao:dtc:1` (DTC).
- **MSO (Mobile Security Object)**: Contains the digests of all items and the Issuer's signature.

### DeviceSigned
Device-signed part (Holder Binding). Proves that the device holding the mDoc is the authorized one.
- **DeviceKey**: The public key bound to the mDoc.

## 3. Mapping from CitizenIdentity

| CitizenIdentity Field | mDL Namespace Element | DTC Namespace Element |
|---|---|---|
| `full_name` | `family_name` + `given_name` | `family_name` + `given_name` |
| `birth_date` | `birth_date` | `date_of_birth` |
| `identity_number` | `document_number` | `document_number` |
| `issuing_authority` | `issuing_authority` | `issuing_authority` |
| `expiration_date` | `expiry_date` | `expiry_date` |
| `photo_data` | `portrait` | `portrait` |

## 4. Implementation Strategy (Rust)
1. Use `ciborium` for CBOR serialization.
2. Use `coset` for COSE Sign1 structure.
3. Integrate with `IdentityController` to allow `to_mdoc()` export.

### DTC Specifics (ICAO TR Digital Travel Credentials)
- **Namespace**: `urn:icao:dtc:1`
- **Data Elements**: Closely mirror DG1 and DG2 from ICAO 9303.
- **Type 1**: Derived from ePassport. The device (smartphone) reads the physical passport and creates a DTC signed by the device key, potentially referencing the original government signature (Passive Authentication data).
